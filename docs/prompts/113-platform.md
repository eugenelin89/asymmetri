## Decisions

- Direct Three.js/WebGL2, separate imperative engine and React information UI.
- Real City footprints/streets/parks, simplified dated shoreline, flat terrain and
  explicitly illustrative heights. No full BC extract, OSM data or large LiDAR.
- Include bounded arcade driving; reject water/buildings/off-street movement.
  Bridge driving and realistic terrain are absent and labelled accordingly.
- Six original sourced place summaries and procedural models; no reference code
  or media copied. MIT scope is explicit; City data and Three.js retain notices.
- Use public-source GitHub Actions as a temporary Linux build environment matching
  Node 22.23.1, without production secrets or automatic deployment. Existing SSH
  and complete candidate/rollback activation remain authoritative.
- Update Next/eslint-config-next to 16.4.3 and compatible fast-uri to remediate the
  existing production audit. Keep React and the Sharp override unchanged.

## Implementation

controls, fullscreen, reset, pause/resume with resource cleanup, no-WebGL error
fallback and no-JavaScript summaries. Scoped CSS preserves the existing identity.
The offline builder produces a ~184 KB snapshot and provenance manifest. Shared
precision fixes a shoreline topology defect found during development.

## Lessons learned

Apply shared geometric precision before polygonizing clipped coastlines; otherwise
near-coincident endpoints can incorrectly classify the entire extent as water.
Public code licences do not automatically license municipal datasets or media.

## Follow-up ideas

waterfront coverage and later walking/history/proposal experiences.
