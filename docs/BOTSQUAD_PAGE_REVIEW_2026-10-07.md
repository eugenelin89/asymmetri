## Public truth boundaries

- Current: persistent identities/history; direct/peer conversations; working groups; authorized
  public research/knowledge; bounded engineering; isolated granted browser work; evidence;
  durable follow-ups. One company, eight workers and two active executions are current limits.
- Engineering: bounded repositories and dependency-free Node recipes. This is not a general
  language/package environment and does not establish Motion iOS build support. No arbitrary
  deployment or validated authenticated-push claim.
- Current focus: Personal Operator / Daily Driver reliability, clarity and daily usability.
- Future: easier private access when justified, multiple companies, collaboration/federation
  and further integrations remain deferred possibilities; native iOS is not available.
- Illustration: the Hitting question and seven-stage sequence are a possible workflow, not an
  actual development result or a fixed engine script. Hitting remains planned.
- Asymmetri use: potential research/specification/planning/review/maintenance across Motion,
  the website and future Labs work. Motion is not an engine assumption. Public-site action
  requires separately granted authority. The real supervised pilot is qualified as one
  unmerged documentation change and scheduled review, not an app release or business benefit.
- Control: discussion is not work authorization, text cannot grant permission, and evidence
  remains inspectable. No promise of perfect security, correctness or unattended operation.
- Self-hosting: coordination state on the operator-controlled host; bounded execution context
  may reach configured model services. No offline-inference or public HQ login claim.

## Release procedure

Use the documented unchanged-dependency copy-only deployment: exact-source candidate,
hard-linked unchanged dependencies, no npm install in either linked tree, production
checks/build before activation, then retained previous build and immutable source tag.
Production had roughly 990 MiB available at preflight; avoid new full dependency copies
or deletion of older releases. Preserve a complete pre-change source archive and verify
tracked assets/configuration equality for bounded rollback. Record exact source/build IDs,
paths, checks, final tag and health in the external release receipt, avoiding a self-reference.
